\section*{Executive summary}
The certified reproduction of Liang \emph{et al.} (1997) yields a drain-refined spatial-convergence trio of the peak impact-ionization generation rate $G_{ii}$ at three meshes ($71\times58$, $100\times70$, $141\times85$ on a common frozen energy grid). This report documents a multi-run, multi-environment reproducibility campaign of that trio. Two findings:

\begin{enumerate}[nosep]
\item \textbf{The qualitative verdict is robust and reproduces everywhere tested}: the trio is significantly \emph{non-monotone} ($S_{\mathrm{rev}}\gg1$), so Richardson extrapolation is suppressed and \textbf{there is no justified continuum value of $G_{ii}$}. This holds across every Windows run.
\item \textbf{The absolute peak $G_{ii}$ is \emph{not} reproducible.} It moves with the convergence/gate-trip point ($\sim2\%$), the compute kernel (numba vs.\ pure-Python, $\sim3$--$7\%$), the SciPy version ($\sim3\%$), and -- most strongly -- the \textbf{operating system} ($\sim12\%$ Windows$\leftrightarrow$Linux with \emph{identical} code, Python, NumPy and SciPy versions). The SciPy-version hypothesis was tested and \emph{disproved}: matching the Linux library stack to the Windows reference made the discrepancy \emph{worse} ($-9.1\%\to-12.0\%$).
\end{enumerate}

Peak $G_{ii}$ is a near-null-space, high-energy-tail functional of the distribution, hypersensitive to the platform numerical floating-point path. A staged frozen-state probe (Appendix C) localizes the \emph{first} cross-platform divergence to sparse-system assembly (matrix coefficients differ at $\sim10^{-16}$, single-threaded), upstream of the sparse solve; a single frozen-state solve reproduces to $\sim4\ten{-13}$. Whether that rounding-scale assembly seed, amplified over the nonlinear iteration, fully \emph{accounts} for the $-12\%$ full-run difference is plausible but not yet proved (see Appendix C, ``what is not yet established''). The Sep-24 reference was computed on Windows and reproduces bit-exactly only on Windows. The recommended remedy is to report a well-conditioned integrated observable (and a properly-defined terminal substrate current) rather than a mesh-point maximum.

\section{System, reference, and method}
First-order spherical-harmonic expansion (SHE) of the electron Boltzmann equation in total-energy form, self-consistent with 2D Poisson and hole continuity; nonparabolic Kane band; DOS-weighted acoustic + optical-phonon + Keldysh-surrogate impact-ionization operators. The SHE linear system is solved with LGMRES preconditioned by a physics-split incomplete-LU (\texttt{scipy.sparse.linalg.spilu}); the outer map is Anderson-accelerated ($\text{depth}=6$, $\beta=0.5$). Convergence gate: last-4 cumulative-iteration spread of $G_{ii,\max}$ and $G_{tot}$ $\le 3\ten{-4}$ and outer residual $R_\phi\le 1.5\ten{-3}$.

\textbf{Certified reference (Sep-24, Windows, pure-Python kernel), produced by git \texttt{d30b471}, validated equivalent to the frozen tag:}
\[
G_{ii}=3.075619/2.136180/2.387429\ten{25}\ \mathrm{cm^{-3}s^{-1}},\quad S_{\mathrm{rev}}=737,\ \text{non-monotone, Richardson suppressed.}
\]
Common frozen $H$-grid hash \texttt{b4319bb03303} (591 energy points) across all meshes and all runs.

\section{The decisive platform test}
Hypothesis under test: the Linux discrepancy is caused by the SciPy version. Prediction: pinning Linux to the reference stack (NumPy 2.5.1 / SciPy 1.18.0, Python 3.13.12, numba off) should recover $\sim3.0756\ten{25}$.

\textbf{Outcome: the opposite.} On the matched stack, $71\times58$ plateaued at $2.7067\ten{25}$ ($-12.0\%$) and failed to certify. The 60-iteration trajectory diverges from the reference \emph{at the first chunk}:

\section{Mechanism --- why it fails}
Peak $G_{ii}$ is numerically ill-posed, for three compounding reasons:
\begin{enumerate}[nosep]
\item \textbf{Tail-dominated functional.} $G_{ii}$ integrates the distribution's high-energy tail ($\varepsilon\gtrsim1.5$\,eV), many orders of magnitude below the peak of $f$. It is therefore controlled by a tiny, ill-conditioned part of the solution -- the documented ``near-null-space'': a $10^{-8}$ \emph{linear} residual does not pin $G_{ii}$.
\item \textbf{Floating-point-path-dependent solves.} LGMRES + \texttt{spilu} results depend on summation and pivoting order, which differ between BLAS/LAPACK/SuperLU builds (OS, compiler, SIMD) at the $\sim10^{-15}$ level per operation.
\item \textbf{Amplification by the fixed-point iteration.} Over $\sim\!350$ outer iterations these $\sim10^{-15}$ differences compound, and because $G_{ii}$ lies in the ill-conditioned direction, they are amplified into $\sim10\%$ in the converged peak -- and can shift which plateau the iteration selects, or prevent clean convergence (the hotspot limit-cycle).
\end{enumerate}
Hence identical code and library versions on a different OS give a $-12\%$ peak $G_{ii}$. The same mechanism explains why the numba kernel, the SciPy version, and the gate-trip point each move the value: all perturb the same ill-conditioned direction. The maximum over mesh nodes of a tail quantity is not a numerically well-posed observable.

\section{Remediation}
These are proposed methodology changes to the frozen reference; none has been applied.
\begin{itemize}[nosep]
\item \textbf{Report an integrated observable, not a mesh-point maximum (primary fix).} Quote an integrated generation $\int G_{ii}\,dV$ (well-conditioned, averages out the hotspot floating-point noise) and, for a \emph{terminal} figure, the properly-defined substrate hole current -- the hole flux collected at the body contact including recombination (audit finding F-08). Note $\int G_{ii}\,dV$ is the generation \emph{rate} per out-of-plane width, not by itself the collected terminal current; both are far better conditioned than the mesh-point maximum. This is standard TCAD practice.
\item \textbf{Direct linear solve.} Replace Krylov+ILU with a direct LU factorization where memory permits (raise the existing direct-solve DOF cutoff), removing the preconditioner/Krylov floating-point-path dependence.
\item \textbf{Gate hardening.} Require plateau flatness sustained over multiple chunks with small chunk-to-chunk $\Delta G_{ii}$, and gate on the integrated $G_{ii}$, so ``converged'' means the same thing on every platform.
\item \textbf{Report with a numerical band.} Absolute peak $G_{ii}$ carries a $\sim10\%$ numerical uncertainty; report it as a band $[2.1,3.1]\ten{25}$ with the stated cause -- which is precisely the existing non-asymptotic (YELLOW) conclusion.
\end{itemize}

\section*{Appendix B: Direct platform-FP probe (one-shot, isolated)}
The identical $71\times58$ cold-start coupled solve was run for 3 capped outer iterations on both machines (\texttt{probe\_fp.py}) and the outputs diffed element-wise. The mesh and energy grid are built from element-wise NumPy and are \textbf{bit-identical} across the two operating systems; the only variable is the platform numerical stack.

\textbf{Environment.} Both ran NumPy 2.5.1 / SciPy 1.18.0 / Python 3.13.x, pure-Python assembly, and -- notably -- the \emph{same OpenBLAS version 0.3.33}. Windows: 8 threads, pthreads. Linux: DYNAMIC\_ARCH, runtime SIMD kernel X86\_V3 (AVX2), $\sim$8 cores.

The mechanism is unchanged: a $\sim10^{-16}$ platform floating-point seed, amplified by the ill-conditioning of $G_{ii}$, yields an order-10\% non-portable result.

\section*{Appendix C: Staged causal localization (frozen-input probe)}
Prompted by an independent source audit, a fixed-state probe (\texttt{audit/fixed\_state\_probe.py}) froze ONE $71\times58$ state (mesh, $\phi$, contact map, equilibrium density $n_{eq}$) from the Windows reference, copied the \emph{identical bytes} to both operating systems, and -- single-threaded (\texttt{OPENBLAS\_NUM\_THREADS=1}), pure-Python -- assembled the SHE operator and solved it on each.
\begin{center}\small
\begin{tabular}{l l}
\toprule
quantity & Windows vs.\ Linux \\
\midrule
state $x,y,\phi$, contact map, $n_{eq}$ & \textbf{bit-identical} (SHA-256 match) \\
energy grid $H$, active-state map & \textbf{bit-identical} \\
CSR structure $A.\mathtt{indptr}$, $A.\mathtt{indices}$ & \textbf{bit-identical} \\
$A.\mathtt{data}$ (matrix coefficients) & \textbf{DIFFER} (max rel $1.1\ten{-16}$, last ULP) \\
$b$ (right-hand side) & \textbf{DIFFER} (agree to 16 digits) \\
single solve from frozen state: $G_{ii}^{\mathrm{peak}}$ & $3.0756185\ten{25}$ both (rel diff $3.8\ten{-13}$) \\
\bottomrule
\end{tabular}
\end{center}
\textbf{Localization (what is established).} Cross-platform differences \emph{first become observable during sparse-system assembly}: the CSR structure, energy grid and active map are bit-identical, but the matrix coefficients ($A.\mathtt{data}$) and right-hand side ($b$) differ at approximately floating-point rounding precision ($\sim10^{-16}$, last ULP), and this holds \emph{single-threaded} -- so it is not BLAS thread-reduction order. The likely source is the platform's vectorized elementary functions (\texttt{exp}/\texttt{pow} in the DOS-weighted Fokker--Planck, phonon and impact-ionization coefficients) differing between OS/compiler builds of NumPy/libm. A single frozen-state solve nevertheless reproduces peak $G_{ii}$ across OS to $\sim4\ten{-13}$ relative accuracy, so SuperLU/LGMRES is \emph{not} the primary seed. The positivity clipping (audit finding F-02) is benign on both OSs (clipped and raw $G_{ii}$ peaks identical; tail-negative $\ell_1$ mass $1.5\ten{-14}$).

\textbf{What is NOT yet established.} That the full-run $-12\%$ is \emph{caused} by this $\sim10^{-16}$ assembly seed amplified over $\sim360$ iterations is \emph{plausible but not proved}. The larger full-run differences are \emph{consistent with} amplification during nonlinear iteration, but the present experiment does not distinguish three possibilities: (i) assembly rounding is the dominant source; (ii) other platform-dependent operations also contribute per iteration; (iii) the nonlinear map has strong sensitivity or multiple attracting trajectories. The precise amplification mechanism and the contribution of other platform-dependent operations \emph{remain to be established}.

\textbf{Decisive next tests (pre-registered).} (1) \emph{Single-platform perturbation}: on one machine, perturb the assembly coefficients by $\sim10^{-16}$ relative magnitude each iteration and run the full loop from the same checkpoint with several random seeds; if these consistently reach \emph{different} plateaus, that is direct evidence of nonlinear sensitivity to a rounding-scale seed. (2) \emph{Coefficient replay} (strongest): drive the Linux iteration with the Windows-computed coefficients (or a shared portable elementary-function path); if the long-run divergence is \emph{suppressed}, assembly rounding is confirmed as the dominant source; if it persists, other platform-dependent operations contribute. These are the strongest tests before declaring the root cause closed.

\textbf{Test 1, first result (single-platform perturbation).} Injecting a $10^{-16}$ relative random perturbation into the assembly coefficients each outer iteration on Windows (runtime monkeypatch, no source edit) reproduces the measured cross-platform divergence growth over the first iterations: relative peak-$G_{ii}$ departures from the unperturbed control of $\sim6.7\ten{-13}$, $\sim9\ten{-13}$, $\sim1.7\ten{-10}$ at iterations 0--2, against the Windows-vs-Linux $5.7\ten{-13}$, $2.2\ten{-12}$, $1.5\ten{-10}$ -- the same order at each step. Two different perturbation seeds give distinct trajectories of the same magnitude. This is direct evidence that the nonlinear map amplifies a rounding-scale seed at the observed rate. It does \emph{not} yet establish \emph{different final plateaus}; the full-to-plateau ensemble (control plus several seeds) is the remaining confirmation and is in progress.
